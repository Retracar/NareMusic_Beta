NareMusic_Beta — 项目目标与规则

项目目标
- 基于 Kotlin + Media3 实现高兼容性的 Android 音乐播放器，覆盖 Android 12–15。 
- 使用协程 + StateFlow 做全部状态流分发，便于前端订阅与测试。

分工边界（必须严格遵守）
1. UI（所有页面布局、Compose、XML、颜色、动画、歌词绘制）由前端负责；后端绝不编写任何 UI 代码。
2. 后端职责（由本仓库实现）：
   - 播放器底层逻辑与封装（Media3/ExoPlayer）
   - 后台媒体服务（MediaSessionService）与前台通知管理接口（不实现 UI）
   - 音频焦点、耳机插拔、OEM 音频能力探测与兼容策略
   - 歌词解析与数据模型（仅解析/封装，不绘制）
   - 播放队列管理、权限适配、状态数据流封装（StateFlow）

编码规范（强制）
1. 仅使用 Kotlin；不添加任何 Java 文件。
2. 使用单例管理类（object）或依赖注入管理单实例；对外使用 `StateFlow` 发布状态，不使用回调接口。
3. 类职责单一、方法简短、必要处写简洁注释、命名遵循驼峰法。
4. 主动管理播放器生命周期，`release()` 必须明确调用以避免内存/句柄泄漏。
5. 歌词解析应使用当前构建可正常解析的实现（或仓内自定义解析器），仅负责解析并生产 `Lyrics` 数据模型，不做任何 UI 或动画。
6. 适配高解析音频（24bit / 96k / 192k），并提供设备能力探测工具与降级建议。
7. 对外 API 极简化，隐藏复杂实现细节，方便 UI 层直接调用。

持久化位置
- 文档与规则存放于 `docs/` 目录（本文件：`docs/project-rules.md`）。

变更流程
- 修改播放器核心代码或接口前，请在 `docs/` 创建 PR 说明变更目的与兼容性影响，通知前端同学可能的契约变更。
